# Архитектура «Стилиста»

Личное приложение одного пользователя. Телефон (iPhone 11, Safari) показывает лицо онлайн, сервер на Python разбирает кадры и ведёт сканирование, а потом показывает разметку: что убрать, что подрезать, что оставить, где отращивать. Документ - решения после обсуждения с владельцем; правится вместе с кодом.

## Принципы

1. **Точность важнее скорости.** Тяжёлый анализ идёт на сервере с GPU. Телефон - камера и экран.
2. **Ничего не выдумываем.** Улучшать кадр можно только честно (объединение кадров, шумоподавление). Генеративный апскейл запрещён: выдуманный волосок означает выдернутый нужный.
3. **Ошибаемся в сторону «оставить».** Выдернутый нужный волос растёт неделями, оставленный лишний убирается за секунду. В неуверенных местах приложение спрашивает, а не решает.
4. **Цель считается от текущего состояния.** Нельзя сразу сделать идеал из того, что есть. Есть три слоя: идеал, достижимое сейчас, зоны отращивания. После каждого скана план пересчитывается.
5. **Образ - это пропорции и силуэт, а не координаты.** Стиль хранится как инварианты (контраст, углы, доли лица) и свободные параметры (длины, высоты). Параметры подстраиваются под лицо, инварианты сохраняются.
6. **Ракурсы.** Образ читается по-разному под разными углами (голова на 15° уже другая картина), поэтому и референс, и результат оцениваются в нескольких видах, а не в одном кадре.
7. **Мужской образ.** Края мягкие, вокруг основного контура остаются тонкие волоски. Резкий выбритый контур - ошибка. Подробности: `BROWS.md`.
8. **Лица в git не кладём.** Снимки живут в папке `data/` (в `.gitignore`), сервер защищён токеном.

## Сценарии

- **A. Референсы** (разово на образ): 20-40 фото актёра -> поза головы на каждом кадре -> границы и плотность волос -> перенос в общие координаты лица -> усреднение внутри образа (образы разных лет не смешиваем) -> «пакет стиля» со слоями (ниже).
- **B. Живой сеанс сканирования** (сделано в каркасе): телефон шлёт поток маленьких кадров, сервер отвечает подсказками («темно», «нет резкости», «держите ровнее») и командой «снимай». По команде телефон отправляет полный кадр. Шаги: анфас, повороты на 15° влево и вправо, брови крупно, затем серия кадров, пока вы двигаете волоски пальцем или расчёской. Голосовые подсказки нужны, когда экран не виден.
- **C. Разметка у зеркала:** результат скана - фото с цветной разметкой. Зум пальцами, слои включаются, есть режим «зеркально», чтобы картинка совпадала с зеркалом.
- **D. План по этапам:** из текущего состояния и идеала считается достижимая цель на ближайший срок и список действий. Новый скан через неделю - новый пересчёт.
- **E. Причёска:** карта уровней fade с шагом 0.5 мм, контроль «пора стричься» (особенно виски, лоб, уши), живая подсветка границы.

## Как видим каждый волосок

Сканирование специально двигает волоски: когда вы проводите пальцем или расчёской по брови, волоски смещаются, кожа - нет. Сервер сравнивает кадры серии и по движению отделяет волосы от кожи, находит корень (точка, которая остаётся на месте) и кончик, и тем самым длину и направление роста. Нужные длинные волосы, лежащие «не в ту сторону», видны отдельно от лишних. Тонкие волоски по краю брови (мужской мягкий край) находятся тем же способом и защищаются как «периферийная зона».

Это гипотеза, а не готовый модуль: проверяется на первых реальных сериях.

## Данные

Слои «пакета стиля» (то, что получено из референсов):
1. границы - кривые, привязанные к анатомическим точкам;
2. карта fade с шагом 0.5 мм;
3. плотность и поле направлений роста (брови, борода) с мягким краем;
4. акценты - отдельные метки (прядь из трёх волосков);
5. сочетания (бровь и улыбка, губы, нос) - позже.

Слои «состояния» (то, что получено из скана): ярлык каждого волоска (оставить, оставить как периферийный, подрезать до длины, убрать, неуверенно), карта пустот, масштаб в мм (по банковской карте 85.6×54 мм или по расстоянию между зрачками), история сканов с выравниванием.

## Компоненты

| Что | Где | Состояние |
|---|---|---|
| Клиент: камера, поток кадров, подсказки голосом, полные кадры | `web/` (JS без сборки) | сделано, не проверено на iPhone |
| Диагностика телефона (камера, фонарик, зум, WebGPU, голос) | `web/diag.html` | сделано |
| Сервер: сеанс, подсказки, загрузка кадров, токен | `server/` (Python, FastAPI) | сделано |
| Оценка кадра: свет, блики, резкость, тряска | `server/quality.py` | пороги надо подобрать |
| Проверка позы головы (15°) | отдельный модуль лица | не начато |
| Улучшение кадра по серии (честное объединение) | сервер, GPU | не начато |
| Разбор волосков по серии | сервер, GPU | не начато |
| Разбор референсов | Colab / сервер | не начато |
| Правила бровей и пресеты | `docs/BROWS.md`, затем данные | черновик |
| Сервер на GPU в облаке | выбор провайдера | не выбрано |

Телефон и сервер говорят по двум каналам: WebSocket (`/ws/scan/<id>`, маленькие кадры туда, подсказки обратно) и HTTP (`PUT /api/scan/<id>/<шаг>?frame=N`, полный кадр). Каждый сеанс - папка `data/scans/<id>/` со снимками и `meta.json`. Токен обязателен везде, кроме `/api/health`.

Язык клиента: сейчас JS модулями без сборки, чтобы у владельца не нужен был Node. Когда клиент вырастет, перейдём на TypeScript.

## Риски и открытые вопросы

- **Разрешение iPhone 11 в Safari.** Страница диагностики покажет, сколько пикселей реально отдаёт камера и есть ли фонарик, зум и фокус. Оценка: на 12 см один пиксель около 0.04 мм, волосок брови 0.06-0.1 мм займёт 1.5-2.5 пикселя. На пределе, но видно.
- **Приватность.** Снимки лица идут на сервер. Туннель через сторонний сервис и облачный GPU означают третью сторону. Решаем осознанно (см. `README.md`).
- **Перекрытия.** В плотной середине брови волоски перекрываются; поэтому неуверенное - отдельный ярлык.
- **Что считать «красиво».** Приложение предлагает 3-5 вариантов адаптации и запоминает выбор владельца.
- **Косметика на референсах.** Часть бровей на фото нарисована карандашом, пудрой или татуажем. Цель делится на «достичь волосами» и «достичь косметикой».
