# Стилист: карта проекта

Читайте эту карту первой и открывайте только файлы под задачу.

## Что это
Личное приложение одного владельца. Телефон (iPhone 11, Safari) шлёт видео лица на сервер, сервер ведёт сканирование и подсказывает, что делать с бровями, окантовкой и причёской. Решения и риски: `docs/ARCHITECTURE.md`. Правила и пресеты бровей: `docs/BROWS.md`.

## Где что менять
| Задача | Файл |
|---|---|
| Оценка кадра (свет, блики, резкость, тряска), пороги | `server/quality.py` |
| Шаги сканирования, состояние сеанса, когда сервер говорит «снимай» | `server/protocol.py` |
| API, WebSocket, загрузка кадров, токен | `server/app.py`, `server/config.py` |
| Экран сканирования на телефоне (JS без сборки) | `web/app.js`, `web/index.html`, `web/style.css` |
| Что умеет Safari на телефоне | `web/diag.html`, `web/diag.js` |
| Запуск у владельца на Windows (PyCharm, туннель для HTTPS) | `LOCAL.md` |

## Правила
- Сообщения программы и документы на русском.
- Фото и видео лиц (владельца и актёров) в git не попадают: `data/` и картинки в `.gitignore`. Тестам нужны только синтетические кадры (`tests/helpers.py`).
- Нельзя улучшать кадры генеративными моделями (апскейл, дорисовка): они выдумывают волоски. Только честное объединение кадров и шумоподавление.
- Неуверенное решение по волоску - ярлык «неуверенно», а не «убрать»: выдернутый нужный волос возвращается неделями.
- Пороги в `server/quality.py` стартовые, их подбирают по реальным кадрам iPhone.
- Тесты: `python -m unittest discover -q`. Они не должны трогать настоящий `data/`.
- Основная ветка `main`. Pull request не создавать, пока не попросят.
- Владелец работает на Windows и в PyCharm: проверяйте код, зависящий от ОС (пути, права файлов).
